# Example 03 — Responsive adaptation

## Use case

Adapt a desktop product surface to a narrow or mobile frame without turning it into a miniature desktop layout.

## Input context

- The authoritative desktop frame and its main task
- Required secondary regions, tables, panels, and contextual controls
- Minimum supported widths and platform constraints
- Content lengths, localization risks, and target sizes

## Copyable prompt

```text
Use /figma-product-design-director to adapt the supplied desktop workspace for 390 px mobile and 768 px narrow-tablet frames. Preserve the primary task, content, and visual identity.

For each width, decide what reflows, collapses, overlays, scrolls, hides, or changes priority. Protect reachable primary actions, readable labels, target sizes, focus order, dialog access, and long-content behavior. Collapse or overlay secondary panels before squeezing the main work area. Include reduced-motion direction for any spatial transition. Finish with a responsive-priority critique.
```

## What the skill should examine

Information priority, navigation transformation, density, target size, content wrapping, overflow, panel behavior, modal reachability, state continuity, and motion purpose.

## Expected categories of output

A breakpoint behavior matrix, narrow-frame compositions, reordered content priorities, state notes, and a responsive critique.

## What still requires human judgment

Supported devices, platform conventions, actual browser or app behavior, touch ergonomics, localization, performance, and assistive-technology validation.

No responsive implementation result is claimed by this example.
