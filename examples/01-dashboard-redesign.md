# Example 01 — Dashboard redesign

## Use case

Restructure an existing operational dashboard whose main task is obscured by equal-weight cards or weak action hierarchy.

## Input context

- A current dashboard frame with realistic, sanitized content
- The operator's primary decision and most frequent action
- Required navigation, filters, comparison fields, and states
- Existing brand variables, components, or a reference frame
- Desktop and laptop target sizes

## Copyable prompt

```text
Use /figma-product-design-director to redesign the supplied operations dashboard around the operator's primary decision: identify exceptions that need action and resolve one without losing list context.

Preserve the supplied content, brand variables, and navigation. First define region ownership, information priority, primary and contextual actions, density, and focal points. Choose a list, table, split view, inspector, or other task-appropriate layout instead of defaulting to equal cards. Include relevant default, hover, focus, selected, loading, empty, and error states. Show desktop and laptop priorities. Finish with a critique that records each observed condition, user impact, and smallest reasonable revision.
```

## What the skill should examine

Purpose, hierarchy, region ownership, layout choice, scan density, action placement, component states, overflow, laptop behavior, accessibility review points, and authenticity.

## Expected categories of output

An art-direction brief, layout and hierarchy decisions, a component/state inventory, responsive priorities, proposed frames, and a structured critique.

## What still requires human judgment

Whether the workflow matches real operations, whether data grouping is correct, whether permissions and destructive actions are safe, and whether the implementation meets accessibility requirements.
