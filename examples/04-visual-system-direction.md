# Example 04 — Visual-system direction

## Use case

Extend an existing product into a coherent visual system without replacing its real brand evidence with a generic theme.

## Input context

- Brand attributes and authoritative references
- Existing variables, styles, components, icons, and type choices
- Core product surfaces and high-frequency tasks
- Required semantic states and content constraints

## Copyable prompt

```text
Use /figma-product-design-director to define visual-system direction for this product. Treat the supplied reference frame, brand assets, and existing variables as authoritative; do not invent a competing theme.

Translate the product personality into semantic color roles, text roles, spacing, geometry, surfaces, icon language, layout rules, and only the component families required by the supplied surfaces. Give each proposed signature motif a functional role in comprehension, hierarchy, action, navigation, or brand recognition. Document state behavior and when a component should not be used. Finish with a coherence and reference-fidelity critique.
```

## What the skill should examine

Brand evidence, semantic tokens, typography, color roles, geometry, surface hierarchy, icons, layout rhythm, component contracts, states, and motif purpose.

## Expected categories of output

An art-direction brief, token inventory, component-family scope, layout rules, state guidance, signature motifs, and a critique.

## What still requires human judgment

Brand ownership, trademark use, font and asset licensing, implementation naming, maintainability, localization, and whether the direction feels authentic to users.

No brand-performance or design-quality result is claimed by this example.
