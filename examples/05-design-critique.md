# Example 05 — Design critique

## Use case

Review existing interface frames with a consistent issue format and a whole-flow recheck.

## Input context

- The complete set of relevant frames, variants, and interaction states
- Product goal, primary user, main task, and success condition
- Authoritative references and design-system rules
- Known constraints and unresolved questions

## Copyable prompt

```text
Use /figma-product-design-director to critique these frames without redesigning beyond the supplied scope. Review purpose and information structure, composition, hierarchy, layout, typography, color roles, spacing, component states, interaction feedback, responsive priority, accessibility guidance, authenticity, and reference fidelity.

For every finding, state: observed condition; user impact; confidence; smallest reasonable revision. Separate confirmed mismatches from optional explorations and unresolved assumptions. After the proposed revisions, re-review the complete flow rather than isolated frames.
```

## What the skill should examine

The twelve critique categories in `SKILL.md`, including state coverage, non-color cues, reachability, responsive priority, authenticity, and evidence fidelity.

## Expected categories of output

A prioritized issue ledger, smallest-revision recommendations, open questions, and a final whole-flow assessment.

## What still requires human judgment

Issue priority, business trade-offs, user-research interpretation, implementation feasibility, accessibility conformance, and final acceptance.

No finding, screenshot, or corrected result is claimed by this example.
