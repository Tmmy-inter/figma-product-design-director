# Seven-day distribution plan

This is an evidence-first sequence, not a traffic forecast. A day exits only when its stated evidence exists; otherwise pause rather than carrying an unresolved claim into the next channel.

| Day | Input | Action | Output | Success indicator | Exit condition |
| --- | --- | --- | --- | --- | --- |
| 1 — Real case preparation | Approved sanitized brief, content, references, target frames, Figma access | Run the fixed-variable baseline and skill-assisted protocol; retain failures and human corrections | Completed case record and reviewed screenshot set | Method fields complete; differences and failures are traceable | Human reviewer approves privacy, fixed variables, and observation wording |
| 2 — Community listing | Verified Skill import, case evidence, six gallery exports, publisher identity | Enter listing copy and assets in the current Community interface without publishing until preview review | Final listing preview and verified destination URL plan | Title, description, images, limitations, and support route match source | Exact account and publish action receive authorization |
| 3 — GitHub conversion | Reviewed repository diff, social PNG, metadata plan, version decision | Apply only authorized metadata/social-preview/Release actions after local delivery is accepted | Product homepage, metadata, and optional Draft Release | Signed-out repository view has working first-screen CTA and no unsupported claim | Repository URL, metadata, preview, and release state are independently checked |
| 4 — Figma Forum | Published Community listing or an explicit decision to link only source, real case method | Adapt the problem-led forum draft to current rules and invite specific failure feedback | One contextual forum post | Qualified replies identify failures, constraints, or missing states | Responses are recorded without treating engagement as validation |
| 5 — Targeted outreach | Three approved invitation variants, support route, test instructions | Invite a small, relevant set of designers/builders/practitioners individually | Test invitations and tracked responses | Recipients run or seriously review one real interface | Stop if outreach becomes repetitive, irrelevant, or requests promotion |
| 6 — LinkedIn / X / Reddit | Real case URL, channel-specific copy, approved accounts, current rules | Publish only the formats with complete evidence; customize each channel | Channel posts and final URLs | Clicks or qualified feedback are recorded as observations | All links work; no duplicated spam, vote request, or unqualified result claim |
| 7 — Feedback and revision | Issues, comments, case notes, link matrix, real metrics | Classify instruction defects, agent-execution failures, documentation gaps, and feature ideas | Prioritized second-round change list | Each change maps to evidence and a smallest useful revision | Decide: revise, run another test, or stop; do not infer product-market fit |

## Measurement rule

Record impressions, clicks, saves, tries, repository traffic, issues, and qualified feedback only after the channel reports them. A number is an observation for a dated channel event, not proof of design quality.
