# Contributing

Contributions should improve Product Design Director's Figma-facing product-design instructions, examples, factual documentation, or reviewability.

## Good contribution scopes

- Clarify an ambiguous instruction with a concrete product-design use case.
- Add a missing interaction, responsive, accessibility-review, or critique edge case.
- Repair an unsupported public claim or broken relative link.
- Add a reproducible, sanitized case study that records failures and human corrections.

Avoid adding framework implementation guidance, build tooling, generic marketing copy, unverified outcome claims, or private product material to `SKILL.md`.

## Before opening a pull request

1. Start from the current default branch and keep the change focused.
2. Explain the observed instruction or documentation problem.
3. Preserve the Agent Skills frontmatter and standalone-file boundary in `SKILL.md`.
4. Map public claims to `SKILL.md`, repository history, or an authoritative source.
5. Record the exact validation performed and what was not available.
6. If evidence comes from Figma, include the surface, date, prompt, fixed variables, output failures, and human corrections.
7. Remove credentials, private product data, personal data, and assets you are not authorized to share.

Use the issue templates to discuss a focused change before investing in a large revision.
